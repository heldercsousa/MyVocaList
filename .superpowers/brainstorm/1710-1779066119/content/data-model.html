SongKaraokeUrls — Data Model Design

One song can have multiple YouTube URLs (different uploads, different quality). The table tracks which URL gets used most so the app can suggest the best one next time.

Entity relationship

Song (1) ──────────────── (0..N) SongKaraokeUrl
// A song has zero or many YouTube URLs
// A URL belongs to exactly one song
// No URL is mandatory — song can exist without any

Proposed table fields — select any you want to remove or question

FK

SongId — int NOT NULL

Foreign key → Song.Id. CASCADE DELETE — if song is deleted, all its URLs go too.

PK

Url — string NOT NULL (PK)

Stored as the canonical short form: youtu.be/dQw4w9WgXcQ. Unique — same URL cannot be added twice to the same song. Serves as natural PK (no surrogate needed).

?

Label — string nullable

Admin-assigned nickname: "HD version", "original 1975", "best karaoke". Optional — most URLs won't need one. Max 100 chars.

📊

PlayCount — int NOT NULL default 0

Incremented each time this specific URL is used in a performance. The URL with the highest PlayCount is the "suggested" one next time the song is queued.

🕐

LastUsedAt — datetime nullable

When this URL was last played. Useful as tiebreaker when PlayCount is equal. Also lets the admin see stale URLs ("hasn't been used in 8 months").

⏱

DurationSeconds — int nullable

Video length in seconds. Enables the overlay countdown ("Maria in ~45s"). Admin fills this once, or it gets populated automatically via YouTube oEmbed API (free, no key needed).

📅

AddedAt — datetime NOT NULL

When the URL was registered. Default = now. Used to sort URLs when PlayCount is 0 (newest first).

URL format — short vs full

A

Store short URL — youtu.be/dQw4w9WgXcQ

11-char video ID is the canonical identifier. App normalises any pasted URL (full, short, embed, playlist) to this form on save. Compact in DB, unique, works forever.

B

Store video ID only — dQw4w9WgXcQ

Just the 11-char ID. App reconstructs the URL at launch time. Slightly more flexible (could target YouTube or an alternative player). DB column is shorter.

Suggested-URL logic

SELECT * FROM SongKaraokeUrls
WHERE SongId = @id
ORDER BY PlayCount DESC, LastUsedAt DESC, AddedAt DESC
LIMIT 1
-- First result = suggested URL for next performance

One open question: thumbnail

YouTube exposes free thumbnail images at img.youtube.com/vi/{videoId}/mqdefault.jpg — no API key. Should the Songs page show a thumbnail chip next to each URL in the list? It enriches the UI but adds an image cache concern.
