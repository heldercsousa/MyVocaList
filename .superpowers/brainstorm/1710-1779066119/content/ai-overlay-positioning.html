AI-Aware Overlay Positioning — First AI Feature

The overlay reads the screen to find where lyrics appear, then places itself in the safest zone. Three approaches with different complexity and capability.

The problem it solves

😤

Overlay covers "Bohemian Rhap—" and the singer misses a word

→
😌

Overlay auto-repositions to top-right — lyrics fully visible

Three approaches — pick one

A

Smart Heuristic (No AI)

Karaoke videos follow predictable patterns: lyrics at bottom center (95% of videos), occasionally at top. The app offers 4 snap zones (corners) and remembers the last position per video. Default: top-right corner.

✅ Zero extra permissions
✅ Works offline
✅ Ships now
❌ Doesn't adapt to unusual layouts
B

On-Device ML — Screen OCR

Android ML Kit / Apple Vision reads text regions on screen. App detects where text appears in the video frame and places the overlay in the region with fewest text pixels. No internet needed.

✅ Works offline
✅ Adapts to any layout
❌ Requires screenshot permission
❌ Android 14+ restricts screen capture
❌ ML Kit adds ~8MB to app
❌ Significant implementation effort
C

Claude Vision API — Intelligent Placement

On song start, the app takes one screenshot and sends it to Claude. Ask: "Where on screen are the karaoke lyrics? Which corner is safest for a small overlay?" Response is cached per video URL.

✅ Most accurate
✅ Understands context (not just text)
✅ Result cached per URL (1 call ever)
❌ Requires internet + API key
❌ Same Android 14+ screenshot restriction
❌ API cost per video (tiny, ~$0.001)

Recommended path: A → C

Ship with Option A (4 corner snap zones, default top-right, position memory per URL) — this handles 95% of videos perfectly. Add Option C as an opt-in "smart placement" toggle in a later phase. The cache means Claude is called once per video URL, ever — the result is stored in SongKaraokeUrls.OverlayZone. A real AI feature with minimal cost.

The Android 14+ screenshot wall

Android 14 requires a foreground MediaProjection session to capture the screen — user sees a system dialog on every capture. This is unavoidable for both B and C. However, MyVocaList can work around it: instead of capturing from the overlay process, it can ask the admin to pick the overlay position once manually (drag to corner), then store it. No screenshot needed. The AI approach (C) becomes an optional enhancement, not a requirement.
