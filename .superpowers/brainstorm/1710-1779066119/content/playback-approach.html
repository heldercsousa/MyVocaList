YouTube Playback — How should the app launch karaoke videos?

This is the biggest architectural decision for the YouTube integration. Each approach has real trade-offs for a live karaoke event setting.

A

Launch YouTube App (External)

App stores the URL. When a performance starts, the app opens the YouTube app (or browser) with the video. The screen is then handed over to YouTube.

Pros

  • Zero implementation complexity
  • Full YouTube controls (quality, captions, seek)
  • Works on all devices without restrictions
  • No YouTube API key or quota needed

Cons

  • User leaves the app — queue management paused
  • No way to auto-detect when song finishes
  • Admin must manually return to app after each song
B

Embedded WebView (In-App Player)

App opens a full-screen WebView with the YouTube IFrame Player. Video plays inside the app. Admin stays in control of the queue.

Pros

  • App stays active — queue visible while video plays
  • Can detect video end event (IFrame Player API)
  • Professional, integrated UX
  • Can auto-advance queue on song end (future)

Cons

  • YouTube ToS restricts IFrame embedding in native apps
  • iOS WebView cannot autoplay YouTube (requires user tap)
  • Requires internet connection (no offline)
  • More complex to implement and test
C

Hybrid — External Now, Embedded Later

Start with Option A (launch YouTube app) for this spec. The data model is designed to support embedded playback in a future iteration.

Pros

  • Ships fast — zero playback complexity now
  • Data model (SongKaraokeUrls table) is future-proof
  • ToS issues resolved at the right time (not now)
  • Real-world usage will inform the UX before building embedded

Cons

  • Admin still leaves the app per performance
  • Two-phase delivery — embedded comes in a later spec

Context for live karaoke events

At a live event, the admin typically connects a second screen (TV/projector) to the phone/tablet. Option A works fine if the YouTube app fullscreens to the second display. Option B would allow the queue UI to stay on the admin device while the video plays on the external display.
