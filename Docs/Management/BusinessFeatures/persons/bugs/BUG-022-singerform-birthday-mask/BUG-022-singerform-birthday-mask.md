### SingerForm (Person form) — Birthday field mask does not auto-insert "/" separator

**Origin**: Found by Helder during emulator smoke test of the Singer form validation task (BACKLOG "03 - Update Singer form", 2026-07-01), after the form was already marked ✅ Done.

**Symptom**: When typing the birthday value, the "/" date separator is not automatically inserted between day/month/year segments as is standard in masked date inputs. The user must type the slash manually.

**Additional requirement**: The literal "/" separator character must never be persisted to storage — only the actual date value (or digit segments) should be stored.

**Constraint from Helder**: Do NOT hand-write custom masking logic (no manual `TextChanged` slash-insertion code). Use a built-in masking capability of the control already in use (DevExpress MAUI `dxe:TextEdit`/`dxe:DateEdit` mask support) — see `devexpress-patterns.md` / Context7 DevExpress MAUI docs for the exact `MaskType`/`Mask` API for the installed DevExpress version.

**Severity**: **Minor** — cosmetic-only. Prior to this fix, the "/" was never hand-typed-then-corrupted in storage: the user typed it manually and it was persisted in exactly the same `DD/MM` string format (`Person.BirthdayDayMonth`) that `PersonService.ValidateBirthday`'s regex (`^(\d{1,2})/(\d{1,2})$`) already expects and that is the intentional, previously-confirmed day/month-only birthday mechanism. No data-integrity issue existed — only a UX gap (user had to type the separator manually).

**Status**: **Fixed** (2026-07-01). Added `Mask="00/00"` and `MaskPlaceholderChar="_"` to the birthday `dxe:TextEdit` in `PersonFormPage.xaml` (`.claude/library/devexpress-patterns.md` § DateEdit / masked keyboard entry and `.claude/library/dialogs-validation.md` § Masked inputs — dates already documented this exact pattern). No hand-written masking code added. `PersonService.ValidateBirthday`'s regex contract and the persisted `DD/MM` string format are unchanged — the fix is purely additive on the existing `TextEdit`.

**Design-question note (residual, low-confidence-verified risk):** DevExpress TextEdit masking has a documented `MaskSaveLiteral`-style property family (WPF/MAUI editors) controlling whether mask literal characters (the "/") are included in the bound `Text` value. The exact MAUI default could not be confirmed from official docs (DevExpress doc pages returned HTTP 403 to automated fetch) or from Context7 (unavailable this session), and the existing `PersonFormViewModelTests` set `PersonBirthday` directly at the ViewModel layer — they do not exercise the real DevExpress masking engine, so a green test run does **not** empirically confirm literal-inclusion behavior. Based on the general convention that masked *text* editors (as opposed to typed-value editors like `DateEdit`) include literals in their bound string value by default (no separate typed backing value to reformat from), and the internal docs' "never persisted" language referring specifically to the `DateEdit`/typed-value approach, the additive-only fix was implemented without a compatibility shim. **Recommend Helder confirm on next emulator smoke test** that "15/03" (with slash) is what reaches `PersonBirthday`/validation after typing through the new mask; if the slash is found to be stripped, add a minimal one-line normalization in `PersonFormViewModel.ApplyBirthdayValidation`/`SaveAsync` (not hand-written masking) to re-insert it before validation.
