- **07/21/2026** - amend - **Inline Trivial Fix (ITF) lane — bounded orchestrator-inline-edit exception (Helder-approved; closes BACKLOG DevCycleCraft 2026-07-12 "allow inline trivial-task execution to save tokens").** **Old rules:** `workflow.md` Rule 2 — all coding is done by subagents, the orchestrator handles shell-only steps; `orchestrator.md § Orchestrator Read-Scope` — the orchestrator never reads `.cs`/`.xaml` source files. **What was wrong:** both are correct for any change with design content, but at the bottom of the size distribution they force a ~25–35k-token subagent round-trip (briefing + cold-start context + exploration + report + orchestrator re-reads report) for a fully-diagnosed one-line fix the orchestrator could apply for ~500 tokens, because it already holds the diagnosis context. Multi-declaration chaining is a prose violation auditable via the per-declaration task-log lines. **C6 consequence, deliberate:** since a regression test is either a second file or > 5 lines, any bug requiring one dispatches — per `bug-tracking.md` that means Critical always dispatches and Major dispatches wherever testable, leaving the lane to Minor bugs, UI-only Major bugs verified by manual E2E, and non-bug trivia. **Grants no exemption** from the worktree HARD RULE (Guard 1 retains priority), component governance, regression-test requirements, or any `[Unamendable]` constitutional constraint (Guard 2 runs ahead of Guard 3), and imposes **no bound on implementor subagents** — the marker is worktree-local precisely so implementors in their own worktrees never see it. Also updated the `PostToolUse` Agent-matcher hook's reminder text, which previously told agents "the Stop hook will auto-commit at session end." **Root cause:** Claude Code's `Stop` event fires after every response turn, not only true session end (same failure mode already diagnosed and fixed for a different hook — see 06/27/2026 entry below). This produced 254 identical no-information "chore: auto-commit…" commits repo-wide, 41 of which touched `Docs/Management/BACKLOG.md` (82% of all BACKLOG-touching commits), making BACKLOG.md's real change history unreadable in `git log`, and created risk of pushing partial/mid-task work to the checked-out branch without any human or subagent-exit-checklist verification. Discovered while investigating why BUG-020 (fix commit `3b2cb75`, confirmed present and un-reverted on `develop`) still appeared "not fixed" during on-device testing — root cause there was separate (fix verified only via build+unit tests, not on-device repro, per its own BACKLOG note), but the noisy auto-commit history made it hard to trust the trail while investigating.
